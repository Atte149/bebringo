# E2E-сценарий Bebringo

Полное покрытие MVP: каждый экран, каждый переход, каждая ветка ошибки.
Документ одновременно является чек-листом приёмки и основой для автоматизации.

**Версия приложения:** 0.1.0 (`org.dueattendant149.bebringo`)
**Среда:** Android 8.0+ (minSdk 26), проверять на API 35.

---

## 0. Подготовка стенда

### 0.1 Эмулятор

```bash
export JAVA_HOME=/var/home/dueattendant149/toolbox/jdk-21.0.12+8
export PATH="$JAVA_HOME/bin:$PATH"
export ANDROID_HOME=/var/home/dueattendant149/android-sdk

# если AVD ещё нет
yes | $ANDROID_HOME/cmdline-tools/latest/bin/avdmanager create avd \
  -n bebringo -k "system-images;android-35;google_apis;x86_64" --force

# запуск без окна (скриншоты снимаем через adb)
$ANDROID_HOME/emulator/emulator -avd bebringo -no-window -no-audio \
  -no-snapshot -gpu swiftshader_indirect &

adb wait-for-device
adb shell 'while [ "$(getprop sys.boot_completed)" != "1" ]; do sleep 2; done'
```

### 0.2 Установка и чистый старт

```bash
gradle assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell pm clear org.dueattendant149.bebringo   # чистые данные
adb logcat -c
adb shell am start -n org.dueattendant149.bebringo/.MainActivity
```

### 0.3 Наблюдение

```bash
# падения и ошибки
adb logcat -d *:E | grep -i bebringo

# скриншот текущего экрана
adb exec-out screencap -p > /tmp/opencode/e2e-<ID>.png

# дамп иерархии для проверки текстов
adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml
```

### 0.4 Управление временем

Проверка стрика и SRS требует смены даты:

```bash
adb shell su 0 date -s "2026-11-09 19:00:00"   # только на root-эмуляторе
adb shell settings put global auto_time 0
```

На обычном устройстве — ручная смена даты в настройках.

## 2. Сценарии

Формат: **шаги → ожидание**. Если ожидание не выполняется — дефект, номер фиксируется.

### 2.1 Первый запуск

**E2E-01. Чистый старт**
1. `pm clear`, запустить приложение.
2. Ожидание: экран «Для чего вы изучаете румынский?», четыре варианта, кнопка «Продолжить» внизу, «Пропустить» справа сверху.
3. Ожидание: в логах нет `FATAL EXCEPTION`.

**E2E-02. Выбор цели**
1. Нажать «Путешествия».
2. Ожидание: строка подсвечена, галочка справа, остальные не подсвечены.
3. Нажать «Продолжить».

**E2E-03. Якорь**
1. Ожидание: заголовок «Когда вам удобно заниматься?», чипы времени и события.
2. Выбрать «утром» и «кофе».
3. Ожидание: карточка-предпросмотр содержит обе выбранные фразы.
4. Нажать «Продолжить».

**E2E-04. Плейсмент**
1. Ожидание: «Проверим, с чего начать», полоса «Задание 3 из 12», четыре варианта.
2. Нажать «Продолжить».

**E2E-05. Форсаж и финиш**
1. Ожидание: «Первый блок уже начат», «2 из 5», чипы `telefon`, `cultură`.
2. «Начать с третьего шага» → экран «Всё готово» с тремя строками.
3. «Начать первый блок» → главный экран.
4. **Проверка сохранения:** полностью закрыть приложение (`am force-stop`), запустить снова.
5. Ожидание: онбординг **не** показывается, сразу главный экран.

### 2.2 Главный экран

**E2E-06. Первое состояние**
1. Ожидание: заголовок «Bebringo», стрик «0 дней», карточка урока с названием первого блока курса («Bună ziua»), «часть 1 из 2», «Осталось шагов: 10 из 10», кнопка «Начать урок».
2. Ожидание: строка «Сегодня: 0 мин · частей: 0».

**E2E-07. Переходы**
1. Тап «Чтение» → список текстов.
2. Назад → главный.
3. Тап «Чат» → список сценариев.
4. Назад → главный.
5. Тап «Слово дня» → экран слова, слово и перевод непустые.
6. Назад → главный.

**E2E-08. Нижняя навигация**
1. Тап «Прогресс» → экран прогресса, вкладка подсвечена.
2. Тап «Профиль» → профиль.
3. Тап «Главная» → главный.
4. Ожидание: на экране урока нижней навигации нет.

### 2.3 Урок: типы шагов

Блок «Bună ziua» состоит из: узнавание, слух, ввод, узнавание, сборка.

**E2E-09. Узнавание**
1. Ожидание: заголовок «Что это значит?», крупное слово `Bună ziua`, 4 варианта.
2. Выбрать неверный.
3. Ожидание: вариант подсвечен, кнопка «Проверить» активна.

**E2E-10. Слух**
1. Тап «Продолжить» после проверки → шаг слуха.
2. Тап «Прослушать».
3. Ожидание: слышна румынская фраза (или тишина, если в системе нет румынского голоса — проверяется по логу `TtsPlayer`).

**E2E-11. Ввод с диакритикой**
1. Перейти к шагу «Напишите перевод».
2. Ожидание: поле ввода и полоска `ă â î ș ț` над клавиатурой.
3. Нажать `ș` → символ добавляется в поле.

**E2E-12. Сборка фразы**
1. Перейти к шагу «Составьте фразу из слов».
2. Ожидание: русский промпт в карточке, плитки слов, пустая область ответа.
3. Нажать плитки в правильном порядке.
4. Ожидание: слова появляются в области ответа в порядке нажатия.

**E2E-13…18. Остальные типы**
Проверяются на других блоках курса (по одному на тип):

| ID | Тип | Блок | Проверка |
|---|---|---|---|
| E2E-13 | Образ | нет в A1 пока | пропустить, отметить как непокрытое |
| E2E-14 | Диктовка | нет в A1 пока | пропустить |
| E2E-15 | Трансформация | b10 «Am ajuns» | поле ввода, инструкция «Поставьте в прошедшее время» |
| E2E-16 | Вплетение | демо | абзац с русским словом другим цветом |
| E2E-17 | Пробег | демо | таймер «60 сек», текст |
| E2E-18 | Диалог | демо | транскрипт, вопрос, варианты |

### 2.4 Проверка ответов

**E2E-19. Верный ответ**
1. Выбрать правильный вариант, «Проверить».
2. Ожидание: блок не показывает ошибку, кнопка меняется на «Продолжить».

**E2E-20. Неверный ответ**
1. Выбрать неверный вариант, «Проверить».
2. Ожидание: карточка ошибки с правильным ответом и объяснением, кнопка «Продолжить».

**E2E-21. Диакритика прощается**
1. Ввести `buna dimineata` вместо `Bună dimineața`.
2. Ожидание: ответ засчитан, но в разборе есть пункт про диакритику.

**E2E-22. Строгая диакритика**
1. Профиль → «Диакритика» → включить «Строгая проверка».
2. Повторить E2E-21.
3. Ожидание: ответ не засчитан, тип ошибки — диакритика.

**E2E-23. Пустой ответ**
1. Нажать «Проверить» без ввода.
2. Ожидание: ошибка «Ответа не было», стрик не страдает.

### 2.5 Завершение блока

**E2E-24. Разбор**
1. Пройти все 5 шагов первой части, на последнем — «Завершить блок».
2. Ожидание: экран «Часть 1 из 2 завершена», счёт «N из 5», до трёх карточек ошибок, кнопка «Продолжить урок».
3. Нажать «Продолжить урок», пройти вторую часть.
4. Ожидание: «Урок завершён!», счёт «N из 10».
5. Если ошибок не было — «Ни одной пометки — слова добавлены в интервальное повторение FSRS.»

**E2E-25. Прогресс сохранён**
1. «На главный экран» → главный экран.
2. Ожидание: стрик «1 дней», «Сегодня: N мин · частей: 2», карточка показывает следующий урок/сцену.

**E2E-26. Возврат в незакрытый блок**
1. Начать урок, пройти 2 шага, нажать «назад».
2. Ожидание: диалог «Выйти из урока?», прогресс сохранён.
3. Снова «Продолжить» → урок открывается на 3-м шаге, счётчик «3 / 5» текущей части.

### 2.6 Повторения

**E2E-27. Отдельная сессия повторения**
1. Закрыть урок, на следующий день открыть главный экран.
2. Ожидание: если есть созревшие карточки, появляется строка «Повторение · карточек: N».
3. Открыть повторение: до 10 шагов, по одной карточке на лемму, без новых слов урока.
4. Ожидание: в новом уроке повторений прошлых слов нет.

**E2E-28. Долг не показывается**
1. Пропустить два дня (смена даты), открыть приложение.
2. Ожидание: **нигде** нет числа просроченных карточек, нет слова «долг».

**E2E-29. Порция под сессию**
1. После пропуска открыть урок.
2. Ожидание: урок — 2 блока (10 шагов), повторение не встраивается в него; отдельная сессия повторения не больше 10 карточек.

**E2E-73. Нехватка места / битый файл**
1. Импортировать повреждённый JSON.
2. Ожидание: сообщение об ошибке, база не повреждена.

### 2.19 Языковая гигиена

**E2E-74. Нет английского**
1. Пройти все экраны с включённым дампом иерархии.
2. Ожидание: в видимых текстах нет латиницы, кроме румынских слов и названий.
3. Автоматически: `grep -rn "string=\"[A-Za-z]" app/src/main/res/values/strings.xml` — пусто (кроме `app_name`).

### 2.20 Производительность

**E2E-75. Холодный старт**
1. `adb shell am force-stop`, затем `am start -W`.
2. Ожидание: `TotalTime` до 2500 мс.

**E2E-76. Плавность**
1. Пройти блок, листая шаги.
2. Ожидание: без ANR, без пропущенных кадров в `dumpsys gfxinfo` выше 5%.

### 3.2 Что добавляется как instrumentation

Пакет `app/src/androidTest/`. Минимальный набор, который стоит написать:

| Тест | Покрывает |
|---|---|
| `OnboardingFlowTest` | E2E-01…05, сохранение флага |
| `LessonFlowTest` | E2E-09…12, 19–24 |
| `StreakPersistenceTest` | E2E-30…33 с подменой часов |
| `RestartTest` | E2E-05, E2E-72 |

Каркас:

```kotlin
@RunWith(AndroidJUnit4::class)
class OnboardingFlowTest {
    @get:Rule val rule = createAndroidComposeRule<MainActivity>()

    @Test fun completesOnboarding() {
        rule.onNodeWithText("Путешествия").performClick()
        rule.onNodeWithText("Дальше").performClick()
        rule.onNodeWithText("Дальше").performClick()
        rule.onNodeWithText("Продолжить").performClick()
        rule.onNodeWithText("Начать с третьего шага").performClick()
        rule.onNodeWithText("Начать первый блок").performClick()
        rule.onNodeWithText("Bebringo").assertIsDisplayed()
    }
}
```

Зависимости для этого: `androidx.compose.ui:ui-test-junit4`, `androidx.test.ext:junit`,
`androidx.test:runner`, `debugImplementation ui-test-manifest`.

## 4. Критерии приёмки MVP

MVP считается принятым, когда:

1. **E2E-01…08** проходят: онбординг, главный, навигация.
2. **E2E-19…26** проходят: урок, проверка, разбор, сохранение прогресса.
3. **E2E-30…33** проходят: стрик, заморозка, ремонт.
4. **E2E-52…53** проходят: копия создаётся и содержит все разделы.
5. **E2E-57…58** проходят: телеметрия пишется и выгружается.
6. **E2E-60…61** проходят: компактный виджет работает.
7. **E2E-66** проходит: урок целиком офлайн.
8. **E2E-74** проходит: английского нет.
9. **E2E-75** проходит: холодный старт до 2.5 с.
10. **Нет падений** в `logcat` за весь прогон.

Остальные сценарии — желательны, но не блокируют приёмку.

## 5. Известные ограничения текущей сборки

| Ограничение | Сценарий |
|---|---|
| Шаги «образ», «диктовка», «вплетение», «пробег», «диалог» не входят в A1-контент | E2E-13, 14, 16…18 не покрываются на живом курсе |
| Плейсмент демонстрационный | E2E-04 проверяет только вёрстку |
| Чтение на демо-абзацах | E2E-35…38 проверяют механику, не объём |
| Аудио — системный TTS | если в системе нет румынского голоса, звучит фолбэк |
| Ремонт работает только за вчера | E2E-34 |
| Импорт бэкапа без выбора файла в UI | E2E-56 проверяется через прямой вызов |
